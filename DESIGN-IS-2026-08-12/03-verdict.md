# Verdict

**REDESIGN.** TutorMind's mobile chat home screen scores 10/30 against the Rams principles, with no principle above a 2 — the prior "mobile redesign" pass (commit `90f83b1`) changed the shell (hamburger → bottom nav) without resolving the underlying accretion problem: two competing CSS scales fighting over the same elements, ~130 lines of admitted-dead CSS still shipping, duplicated affordances (two mic buttons, two Settings entry points, a breakpoint-split New-chat button), a decorative element (the pulsing glow orb) that dominates an otherwise empty screen, and a centerpiece nav icon that looks tappable and isn't.

**Why redesign and not refine:** total is well under the REFINE threshold (20), and the failures aren't cosmetic — they're structural (dead CSS actively shadowing live CSS, a broken affordance in the most prominent nav position, missing Error/Success states) in a way that a targeted style pass won't fix. This confirms the user's "still sucks, design and all" read: it's not one bad screen element, it's the whole surface.

**Top 5 highest-leverage moves:**

1. **#10 (as little design as possible) — Delete, don't restyle, the dead weight first.** Remove the 128-line dead Mobile Level Selector block (`mobile.css:632-759`, self-commented as dead), the unused `.gradient-orb` pulse animation and unused `.suggestion-pills-row` CSS (`ui-overhaul.css`), and collapse the duplicate voice controls (`.voice-btn` vs `#voice-mode-trigger`, `tutor_mysql.php:546`/`549`) and duplicate Settings entry points (`#bottomNavSettings`/`#profileSheetSettings`) down to one each. Evidence: 01-evidence.md §A.
2. **#4/#6 (understandable/honest) — Fix or remove the dead center nav icon.** `.bottom-nav-brand` (`tutor_mysql.php:719-721`) sits in the visually dominant center slot of the bottom nav, looks tappable, and has zero click handler in `chat-interface.js`. Either wire it to something (e.g. home/new-chat) or strip it from the tab bar entirely. Evidence: 01-evidence.md §C.
3. **#3 (aesthetic) — Collapse to one spacing/type/color system and fix the cascade bug.** mobile.css's own greeting-size override (`mobile.css:478-482`) is silently beaten by an `!important` rule in `ui-overhaul.css:5697-5701` — mobile.css is currently losing fights it should win. Consolidate the two overlapping scales (9+ spacing values, 10+ type sizes, 67+ literal colors) down to a small token set, and fix the specificity so mobile.css actually governs mobile. Evidence: 01-evidence.md §B.
4. **#3/#4 (aesthetic/understandable) — Fix the WCAG-failing bottom nav contrast.** `.bottom-nav-item` text/icon color `#94a3b8` on its translucent white background computes to 2.56:1 — fails AA on the primary navigation surface. Evidence: 01-evidence.md §B.
5. **#5/#9 (unobtrusive/environmentally friendly) — Give the idle screen actual content, and gate its one animation.** Replace the empty space below the input (currently just a permanently-pulsing decorative orb with no `prefers-reduced-motion` guard) with something task-relevant — recent chats, suggestion chips (the CSS for this already exists at `ui-overhaul.css:673-675` and is simply never populated) — and wrap the orb's animation in a `prefers-reduced-motion` guard. Evidence: 01-evidence.md §B, §D.
